## 5. Remaining limitations and classified risks
- Finding #1 (Investigate Now — owner to adjudicate). The Cardano adapter (`src/funding/cardano/adapter.ts:387-390`) treats a settle() timeout/transport failure as `settlement_indeterminate` and returns `invalid('settlement_indeterminate: retry with the identical payment header')` — `code:'payment_invalid'` with NO `settlementAttempted` flag. This is a deliberate, test-locked (`tests/unit/cardano-adapter.test.ts`), rail-specific idempotent-retry design and is double-spend-guarded: the gateway refuses re-funding while `payment_state='unknown'` (`service.ts:645-647`), and facilitator tx-id dedup returns `payment_replayed`. Canonical state stays `awaiting_funding` + `unknown` with `recover_funding` enqueued, and the MCP customer-facing outcome is `confirmation_pending` (tools re-read canonical state). The only defects are (a) a misleading `funding.rejected` audit EVENT and (b) a payer POST retry that the gateway safely refuses. It was NOT changed here because doing so would alter a financial rail's recovery model, and the original WS1 file scope named only the Sui and Solana adapters. Owner options: leave as-is (guarded), or extend the WS1 confirmation-pending semantics to Cardano's indeterminate path (rail-behavior change, needs its own fixtures + review).
- Finding #2 (Accept Risk — documented). `tests/integration/postgres.test.ts:36` asserts `schema_migrations` count 12 but 13 migration files exist (a stale count; a 1-char test fix is available if the owner wants it in scope). Three `tests/integration/human-orchestration.test.ts:54-70` cases assert quote-time funding-readiness filtering (MISSING_CONFIG / ACCESS_BLOCKED / sandbox) that the code deliberately moved to purchase time (`fundingOptionsFor` builds quote options from `acceptedAsset()` config only; `fundingReady` runs at `createPurchase`). Owner to adjudicate: update the tests to the current design, or restore quote-time filtering. Not modified here to avoid changing financial-readiness behavior outside the five workstreams.
- WS5 latency changes are bounded, demonstrated improvements on the existing Playwright/Chromium path, not a guarantee of future ingress/latency on Render Free or of Shopify sandbox responsiveness. All fail-closed guards and the three-equal-observations rule are preserved.
- WS5b media is genuine merchant variant imagery only (type=image, safe https, max 5). Product-level raw description/images remain discarded; no inferred enrichment is presented as a merchant fact.
